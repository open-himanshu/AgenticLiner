**Galgotias University SparkX 3.0 Innovation Challenge | Track Challenge #1**

## 1. System Overview & Architecture
AgenticLiner is an event planning and management application for university departments and student organizations.

The application includes workflows for **campus facility requisitions, inventory allocations, academic timetabling, registrations, approvals, and notifications**. Kavach provides transactional safeguards for operations routed through its guarded methods; it does not establish that all application state is free of errors.

```
+-----------------------------------------------------------------------------------+
|                            ORGANIZER & ATTENDEE UI                                |
|  Brief Intake | Live Autopilot | Timetable Grid | Waitlist Roster | Outbox Monitor|
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                                 FASTAPI GATEWAY                                   |
|   REST Endpoints, Server-Side Rendered Jinja2 Templates, Transaction Coordinators |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                        KAVACH TRANSACTIONAL SAFETY ENGINE                         |
|   SQLite SAVEPOINTS | Application-level safety checks and outbox handling             |
|   (Capacity, overlap, stock, time window, recipient and blast-radius rules)        |
+-----------------------------------------+-----------------------------------------+
       |                                  |                                  |
       v                                  v                                  v
+---------------+                +-----------------+                +---------------+
|  OR-Tools     |                |  Ridge regress. |                | QR-linked     |
|  CP-SAT       |                |  fallback       |                | Certificate   |
|  Scheduler    |                |  Resource Opt.  |                | lookup        |
+---------------+                +-----------------+                +---------------+
```

Campus bookings allocate university venues and equipment inventory directly, and there is no payment step or wallet table. Resource estimates use Ridge regression when enough historical records are available; otherwise the module uses a rule-based baseline.

## 2. Navigating Screens & Workflows

### Role 1: Event Organizers (Clubs, Faculty & Coordinators)

#### Screen #1: Event Planning Copilot (`/`)
- **Purpose**: Input natural language event briefs (e.g., *"Organize a 2-day AI Hackathon for 150 students with coding workshops and cordless mics"*).
- **Features**:
  - **Prompt parsing**: The event-genesis workflow can use a configured Gemini provider and falls back to a deterministic rule-based baseline. Adaptive intake checks for missing information and can return clarification questions.
  - **Task Board**: Displays configured D-7, D-3, D-1, and D-Day tasks with assigned roles.
  - **Campus Logistics Requisition**: Direct requisition of campus equipment (microphones, extension cords, JBL audio systems, student lunch quotas).

#### Screen #2: Autopilot Mode (`/autopilot`)
- **Purpose**: Multi-step event planning and execution, with agent mode available when a provider is configured.
- **Features**:
  - Live execution timeline showing step-by-step tool invocation.
  - The activity timeline displays tool outcomes, including committed or rolled-back requisitions and any returned safety details.

#### Screen #3: Timetable & Schedule (`/schedule`)
- **Purpose**: Session grid generated by the **Google OR-Tools CP-SAT Solver**, subject to the constraints represented in its model.
- **Features**:
  - Displays all sessions, room assignments, allocated speakers, and time slots.
  - **Hero Demo: Speaker Cancels**: Runs the speaker-cancellation workflow, which attempts to reschedule and may stage a schedule-change notice.

#### Screen #4: Printable Event Flyer & Poster (`/flyer`)
- **Purpose**: Event flyer page for viewing event details and sharing.
- **Features**:
  - Displays event headline, venue, dates, agenda highlights.
  - Includes a QR code linked to the university's event-registration page.

#### Screen #5: Attendee & Registration Management (`/attendees`)
- **Purpose**: Management of student registrations and attendance.
- **Features**:
  - Roster table with search and department filtering.
  - Badges showing `Confirmed` or `Waitlisted`.
  - **Gate Check-In Button**: One-click physical check-in marking attendance.
  - **Waitlist promotion**: When a confirmed registration is cancelled, the attendee manager promotes the first waitlisted registration when one is available and stages a notice.
  - **CSV Export**: One-click download of the complete roster (`/api/attendees/export`).

#### Screen #6: Transactional Outbox & Broadcast Center (`/outbox`)
- **Purpose**: Campus notification management implementing the **Transactional Outbox Pattern**.
- **Features**:
  - Shows staged notices (e.g. Schedule Updates, Waitlist Promotions, Urgent Room Changes).
  - Kavach-managed operations can stage notices within a savepoint and mark them as sent as part of the guarded operation. Other workflows may stage notices for later handling.
  - Manual broadcast composer for faculty announcements.

#### Screen #7: Post-Event Analytics & Verifiable Certificates (`/analytics`)
- **Purpose**: Post-event feedback analysis, certificate generation, and lookup.
- **Features**:
  - Rule-based baseline sentiment scorecards (Positive, Neutral, Negative) using keyword hits and optional rating adjustments.
  - Keyword-based theme classification and summaries across Venue, Content, Hospitality, and Organization.
  - **Download Executive Summary Report**: Generates an executive PDF report for the Dean (`/api/reports/executive-summary`).
  - **Certificate Verification Desk**: A QR code links to a certificate-ID lookup against the application database. The lookup checks for a matching certificate record; it does not validate a signature.

### Role 2: Student Participants & Attendees

#### Screen #8: Public Student Registration Form (`/register`)
- **Purpose**: Student signup portal for campus events.
- **Features**:
  - Registration checks event capacity before confirming or waitlisting a request.
  - When confirmed capacity is reached, the registration workflow can place an eligible student on the waitlist.

#### Screen #9: Personalized Participant Experience (`/participant`)
- **Purpose**: Individual attendee dashboard.
- **Features**:
  - **TF-IDF + Cosine Similarity Recommender**: Scores sessions against declared interests and skips recommendations sharing the same start time or slot identifier.
  - **Peer & Faculty Mentor Matching**: Discovers fellow participants and faculty mentors with overlapping interests.
  - **Rule-based baseline Event Q&A Assistant**: Matches query terms against schedule and venue records. Some answers, such as refreshment information, are fixed text rather than database lookups.

## 3. Emergency Speaker-Cancellation Workflow (Hero Demo)
1. Navigate to `/schedule`.
2. Locate the **Hero Demo: Speaker Cancels** button on the top-right toolbar.
3. Click the button to trigger an emergency faculty cancellation simulation.
4. The workflow submits a schedule with a substitute speaker to the CP-SAT solver and stages a schedule-change notice in the Outbox.

## 4. Verification & Audit Guide
To inspect the configured application database with the independent auditor, run:
```bash
python eval/benchmark/independent_checker.py
```
The auditor reports counts and details for the database snapshot it reads, including room overlaps, capacity overruns, speaker clashes, orphan events, held or leaked outbox notices, and foreign-key violations. Results depend on the current database contents; an audit does not prove that unmodeled policies are satisfied.
